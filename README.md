# jaq/li

以海边工作室为入口的个人博客。原图 `assets/IMG_1183.PNG` 的 WebP 副本呈现为全屏动态像素场景，电脑屏幕、加载和转场保留 ASCII。标识及标签页统一使用 `jaq/li`。原生 HTML、CSS、JavaScript，无构建步骤或第三方运行时依赖，可直接发布至 GitHub Pages。

## 本地运行

```sh
cd /workspace/lijia7.github.io
python3 -m http.server 8081 --bind 0.0.0.0
```

通过 HTTP 的 8081 端口访问，JavaScript 使用 ES modules。

## 场景交互

- 中间三个电脑屏幕 → `/tech/`；主屏幕有 `TECH BLOG` 提示。
- 人物 → `/cv/`；`ABOUT ME` 提示常驻，与 `TECH BLOG` 一致。
- 水面上的小黄鸭 → `/life/`；没有可见标签、悬停高亮或鼠标手形提示。键盘访问仍保留无障碍焦点。
- 场景采用等比例 cover 铺满视口，上端裁切量为下端的一半（上 : 下 = 1 : 2）；字符加载预览、静态回退与正式场景保持一致。竖屏可左右滑动探索整个房间；点击区域始终使用原图坐标，与画面一起缩放、移动。
- 内部页面双向跳转采用字符打散/重组与镜头缩放：进入子页拉近，返回首页缩远；系统开启减少动态效果时停用这些动画。右下角可暂停场景，后台标签页停止绘制。

入口多边形与目标链接位于 `site.config.js`，原图尺寸为 1536 × 1024。首页无上传、拖入图片或密度调整功能。

渲染由 `pixel-scene.js` 完成。房间、人物、城市、水面和天空统一使用从原始 PNG 派生的全局像素化底图，保留构图和细节位置，画面不再全局换字或变化字号。`tools/prepare-pixel-scene.cjs` 只在离线准备时运行：逐一处理全部 1,572,864 个原生像素，先在 5×5 邻域内按颜色相近程度清理细碎色差，再在 3×3 邻域收紧原有明暗过渡；结果限制在局部实际颜色范围内，避免锐化产生额外亮边或黑边。去掉上一版的 2×2 平均和 256 色限制，保留衣褶、纸面笔画、细线和暗部层次；只做最多 2 个色道等级的取整，以无损 WebP 保存，母版保持原尺寸，不重绘内容。场景和动画裁片从同一底图提取，天空、水面和室内采用同一套像素处理。原始 PNG 不修改。抠图与运动仍使用原图 1536×1024 坐标；所有场景图层合成后统一采样到 384×256 的公共网格，再用最近邻显示，即像素单元的长、宽各为此前的 4 倍。额外小画布约 0.375 MiB，不逐帧读取像素、不按窗口尺寸增加纹理，不为各动态物体单独对齐网格；三块屏幕从字形到最终合成都保留 3 倍分辨率，使用覆盖屏幕区域的独立画布（1260×570），避免回落到房间的原图像素；主屏字号 5.6、左屏 6.2、右屏 5.8 源图像素，保留透视。主循环目标 60 Hz，云层随主循环逐帧平移，显示屏 24 Hz，动作使用真实时间。暂停、后台标签页与页面切换会停止调度。

`scene-objects.js` 保存海鸥航线、轮廓、水面区域与头发遮挡，供像素场景和保留的旧 ASCII 渲染器共同使用。五只海鸥沿原来的独立曲线飞行并扇翼；浮鸭、船、纸张、罐子等按 `scene-details.js` 和 `scene-floats.js` 的原有周期漂浮。纸张从固定端摆动、衣角轻动、机器人眨眼与换表情、机械云彩色呼吸灯均保留；顶部吊灯每 3.5 秒短暂暗闪一次（约 0.26 秒），仅作用于暖色灯面，随全局暂停和减少动态设置停用；人物躯干和城市保持静止。物体裁片只在初始化提取；完整轮廓包含平板右侧边框、纸张卷边、罐口、手机外壳和玩具车轮。漂浮物裁片使用清晰、不透明的完整轮廓，不携带外围渐变水面；静态补底独立清理约 3 px 的旧边缘。补底按实际水面区域取样，保留暗水面和亮反光，排除相邻物体外壳，避免亮圈和边框残影。鸭子重新按原图补全头顶与右侧高光轮廓，额外去掉与外部相连的蓝色水面，不挖空内部细节；头后左侧棕色纸角与右侧浅色纸面单独延展补底，保留原来的可见纸边，避免漂浮后露出被误填的蓝色水块。纸张以固定端为轴整张变形，不使用水平分条。漂浮物及纸张只在运动变换时使用局部亚像素采样，避免小角度旋转逐列跳到相邻像素行、形成扫过物体的竖线；场景底图仍按原尺寸和最近邻方式显示，无全屏模糊或额外高分辨率画布。海鸥原位置使用邻近天空色修复。`scene-sky.js` 从原图无遮挡的天空区域构建循环纹理，在重叠区域寻找颜色差异最小的连续接缝并保留两侧原生像素，避免宽渐变叠出模糊的双层云边；以每秒 12 源图像素持续向右漂移，约 69.3 秒完成一轮；不再左右往返。单个不透明 CanvasPattern 覆盖原天空，避免循环接缝露出静止云层；`scene-sky-matte.js` 按物体完整轮廓保护告示板、显示器亮边、桌边容器、主城、花盆、窗框，以及右侧架子支撑柱、机器人完整外壳和后方终端；天空不再按全局颜色阈值抠选，避免只留下物体的深色碎边、吃掉高光。左窗与中窗下方的旧蓝色岸线、白色花状物已移除，天空在源图 y=428–429 用两行覆盖度接入 y=430 的海平线；下方残留的灰色岸线以附近的远水面补齐；海天交界另有一次生成的窄幅大气过渡层，颜色取自原图远水面，透明度从上下两侧渐入、渐出并随四个时段一起调色，建筑、柱子、头发和浮标机器人继续遮挡它。最高楼与天线、桌面容器及后方显示器重新按原图定位；柱子旁的蓝色建筑作为完整前景保护，不再被柱边清理规则删除。`scene-edge-matte.js` 仅在已描绘的前景与天空交界的一像素范围内估算混色覆盖度，用内部前景色和当前天空重新合成，清除残留蓝边、粉边，同时保留细杆与亮边。窗台斜板仅沿外侧窄边清除旧蓝天残色。`scene-shelf-matte.js` 用图像工具抠图所得的支架轮廓辅助原生像素分层，保留柱子左侧折弯支架的两根细脚，并对柱子的一像素边界去除旧天空混色。`assets/mattes/shelf-support-prior.png` 仅用于离线重建轮廓（`node tools/prepare-shelf-matte.cjs`），网页不下载该图片；支架的两根细脚按轮廓保护，不再依赖容易被清晰化改变的亮度阈值；主场景采用原始 PNG 的确定性像素整理结果，不采用生成式重制版本。夕阳单独保留。天空调色采用完整的可见天空遮罩，与云层运动遮罩分离，避免窗柱附近出现漏调色的矩形色块。纹理与遮罩仅在初始化生成；动画不读取画布或逐帧分配图像缓存。

`scene-extras.js` 补充十处独立动作：杯口三缕像素蒸汽、小风扇转动、黄色吊牌摆动、窗台植物三组叶片、绿色机器人眨眼与四种表情、右下圆机器人眼睛转动与眨眼、左机架异步活动灯、右机架间歇追逐灯、前景线缆中段浮动、窗前七颗微尘。风扇由 `scene-fan.js` 分为静止背景、三片独立金属扇叶、网罩和轮毂，透明扇叶之间能看到固定背景；`scene-foliage.js` 将吊盆、窗台植物和右侧机架旁的黄绿色垂叶拆成十九组叶片，使用 `scene-deform.js` 连续弯曲、错开相位，茎根与花盆固定；相较初版叶片摆幅增加约 50%，频率增加约 45%，裁片留出完整的摆动空间；每个源像素只分配给一组叶片，三处植物分别统一提取和补底，排除相邻叶片作为背景采样来源。深色轮廓一起移动，跨窗柱部分按窗柱的位置和原有明暗补齐；叶片调色独立于天空遮罩；吊牌在挂点转动，线缆连接端不动。线缆只对小裁片做连续反向采样和预乘透明度插值，避免分条、竖向扫描与暗边。缓存仅在准备阶段提取，逐帧不读取画布、不下载新图、不开独立计时器，随场景统一暂停。

`scene-additions.js` 还加入图示浮标机器人的浮动、双镜头反光和独立天线，以及以下十五处动作（与前一批十处分别计数）：

4. 左上 U 形悬线中段弯曲，两端固定。
5. 桌面小终端的状态矩阵变化。
6. 桌下上排黄色活动灯。
7. 桌下下排橙色活动灯。
8. 右机架上层橙色磁盘指示灯。
9. 右机架下层绿色指示灯。
10. 右侧黄色杯口的蒸汽。
11. 左下水上蓝色书本漂浮。
12. 左下深蓝色封面书本漂浮。
13. 前景米色书本漂浮。
14. 前景独立游戏手柄漂浮。
15. 远景最高楼顶部信号灯短闪。

图示机器人与新增漂浮物复用完整轮廓提取、背景修复和连续采样；身体、天线分开运动。人物身体、座椅和建筑轮廓保持固定。

右上角可手动选择 **清晨 / 中午 / 黄昏 / 夜晚**。首次访问默认黄昏，后续通过 `localStorage` 的 `jaqli.scene-time` 记住上次选择；存储不可用时仍可切换。`scene-time.js` 在首次切换时保存一份纹理原色，在每次选择时分批重新着色，完成后一起提交；返回黄昏恢复原色，无累积滤镜，也不同时保留四套渲染器。天空、水面和室内采用不同照明，夜景保留屏幕、灯泡和眼睛的发光，补充月亮、星光和城市窗灯；中午将低处夕阳替换为高处太阳。几何、互动入口和屏幕清晰度不变。通常播放不运行全图调色或像素回读；暂停、后台、减少动态效果继续约束所有动态。切换时暂停共用时钟，等待纹理提交后按原播放状态恢复；选择记忆也用于返回首页和刷新。

`scene-beacon.js` 单独管理机械云中心的呼吸灯：保留原始灯体轮廓和亮芯，用 2 px 网格、离散色阶缓存四种颜色纹理，避免将压缩噪声变成细碎闪点。夜间周围的反光也用分档像素块和稀疏静态抖动，强度与灯芯同步，不使用模糊或连续空间渐变；纹理只在初始化生成，动画复用共用时钟和小画布。

ASCII 仅用于三块电脑屏幕中的代码、波形、频谱与状态信息，以及开场字符生成、页面切换的字符打散/重组。`screen-content.js` 与 `scene-geometry.js` 保留显示器的四角透视；独立的头发与运动纸张遮罩保证高清屏幕位于前景后方，像素边框保留；暂停、旋转、滑动和转场同步两个画布。水面采用低分辨率像素高光、椭圆涟漪与小反光，限制在实际水面区域，并由漂浮物覆盖。

首屏由独立的 `scene-intro.js` 读取约 9 KiB 的 `assets/scene-seed.webp`，用实际字符逐步形成轮廓。真实下载与物体准备进度驱动生成目标；每次最多新增 280 字、刷新最近 180 字。完整场景就绪后释放临时画布和数组，不强制等待开场动画。正常访问只下载色彩图和约 1.00 MiB 的无损 `scene.webp`；不加载原始 PNG、ASCII 预览、色彩底光、字形图集或旧 Worker 模块。加载失败或禁用 JavaScript 时才下载约 170 KiB 的 `scene-poster.webp`，其 384×256 网格与正式场景一致，入口仍可访问。

旧 `ascii-renderer.js`、Worker 与图集代码暂保留为历史参考及旧画面导出工具，首页不加载它们。`tools/prepare-scene.cjs` 调用全局像素整理流程更新 WebP 和加载色彩图；其中 ASCII 预览/底光输出不参与当前首页。

可使用 `node tools/review-pixel-scene.cjs BEFORE AFTER OUTPUT_DIRECTORY` 导出覆盖全图的 4×4 对照网格，每块都以同样的 2 倍最近邻放大检查。清晰化改善已有像素过渡，不凭空补绘原图未记录的细节；离线处理不增加逐帧计算或画布缓存。

这是可审阅的本地内容快照，不是自动同步服务。当前按来源页面 ID 保持映射；`LIFE` 与年度生活文章进入生活页，技术学习及 AI 相关笔记进入技术页。原文链接与原始分类保留在记录中。可使用公开来源或 Notion 官方导出的 Markdown/HTML ZIP 更新快照，不需要网站读者登录 Notion。

## 页面切换

`navigation-boot.js` 在目标页首帧前读取一次短期转场标记，失败会自动恢复可见；`navigation.js` 管理离场 560 ms、入场 640 ms 的双向切换。`page-particles.js` 从当前可见文本或首页颜色采样生成最多 1,400 个 ASCII 粒子，按各自方向散开并在目标页聚合。摄像机用浏览器合成变换缩放并平移真实页面，不截图重建文字。首页进入子页时推近到 1.95 倍，并朝入口平移；返回首页从 1.95 倍缩远，子页离场缩至 0.58 倍并移位。镜头明显移动期间保留页面可见度，字符粒子使用相同的缩放/位移。加载动画不等待完整场景准备。首屏布局采用未变换的 clientWidth/clientHeight，避免转场缩放改变画面尺寸。

每次动画结束立即销毁粒子与画布，退出/历史返回清理过渡状态，提供计时器兜底；同页锚点、外链、下载、修饰键和系统减少动态效果保留原生行为。同一 pathname 的不同文章 query 也支持转场。只预取目标 HTML，不预取视频或整套场景资源；首页动效在转场期间暂停计算，完成后恢复。

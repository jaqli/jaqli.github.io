# jaq/li

以海边工作室为入口的个人博客。原图 `assets/IMG_1183.PNG` 的 WebP 副本在浏览器中渲染为全屏动态彩色 ASCII。标识及标签页统一使用 `jaq/li`。原生 HTML、CSS、JavaScript，无构建步骤或第三方运行时依赖，可直接发布至 GitHub Pages。

## 本地运行

```sh
cd /workspace/lijia7.github.io
python3 -m http.server 8081 --bind 0.0.0.0
```

通过 HTTP 的 8081 端口访问，JavaScript 使用 ES modules。

## 场景交互

- 中间三个电脑屏幕 → `/tech/`；主屏幕有 `TECH BLOG` 提示。
- 人物 → `/cv/`；`ABOUT ME` 提示常驻，与 `TECH BLOG` 一致。
- 水面上的小黄鸭 → `/life/`；没有可见标签、悬停高亮或鼠标手形提示。键盘访问仍保留无障碍焦点。
- 场景采用等比例 cover 铺满视口。竖屏可左右滑动探索整个房间；点击区域始终使用原图坐标，与画面一起缩放、移动。
- 内部页面跳转有字符消散动画，子页有浮现动画；系统开启减少动态效果时停用这些动画。右下角可暂停场景，后台标签页停止绘制。

入口多边形与目标链接位于 `site.config.js`，原图尺寸为 1536 × 1024。首页无上传、拖入图片或密度调整功能。

渲染由 `ascii-renderer.js` 完成。全景采用不规则点位排布。约 5.6 px 的横向预算、180–300 列及 1.42 的纵横比只用于限制采样数量；字符位置可以跨越初始格点，随后按字号占地相互让出空间，形成不等距的大小字穿插。字体大小和平均采样密度分别控制。字号为 0.50–1.20 倍共八档，间隔 0.10，逐字符混合大小，天空不再向 1.20 收拢。基准权重由 0.50 到 1.20 依次为 3%、6%、10%、14%、19%、22%、16%、10%；0.80–1.00 档合计 55%，其余档位穿插分布。字号使用独立于字形、留白的固定随机种子，仅在初始化或重排时计算；纸张和漂浮物共用这套分布，细小 LED 保留可读性。左右两侧深色区域及两根窗柱的阴影内侧，按亮度与周边细节留下稳定空位，无细节的深色背景可整片留空；天空、云和亮部保留全部字符，城市与高对比轮廓不挖空。以 1920×1080 窗口为例，平均采样预算约 6.40×9.08 CSS px，实际中心间距不固定；约 3.6 万个采样点中保留约 3.3 万个字符；0.80–1.00 档对应约 5.22–6.53 CSS px。海鸥和远景城市始终固定在最小档 0.50；海鸥采样步长缩为原来的 75%，城市在原点位之间增加半格错位采样，仅在建筑轮廓内加密；城市退出字号呼吸动画，海鸥透视缩放不改变字符字号。屏幕与动态物体使用相同的基准字号和范围，通过 ASCII 文本、双通道波形、频谱和状态侧栏保留细节，边缘渐变接回原图反光与边框。水面反光只叠在实际保留的字符上，明亮水面保持完整，深色空位不随涟漪闪烁；人物躯干和手臂保持固定。

首屏优先显示 `assets/scene-preview.webp` 中预先渲染的 ASCII，下载 `assets/scene.webp` 的同时预载 Worker 模块，随后分段初始化动画，保持入口可点击。进度条跟随真实下载字节数、物体准备和字符绘制进度；没有长度头时，下载阶段显示不定进度。原始 PNG 不参与首页下载。静态字符同样复用图集，云纹理生成复用数组，同尺寸重复布局不会重新生成缓存。修改渲染样式或原图后，在静态服务运行时执行 `node tools/prepare-scene.cjs` 更新预览、场景和底光三个资源（需要 ffmpeg、Playwright 和 Chromium）。只调整字体时使用 `node tools/prepare-scene.cjs --preview-only`，重绘首屏预览及底光，保留场景图片的原有编码和颜色。

`scene-style.js` 统一场景字重及色调：700 字重支持小字号，适度提亮中间调和饱和度。`assets/scene-ambience.webp` 是 384×256 的原图色彩底光，由去掉活动物件后的底图离线缩小、柔化生成；深暗部逐渐归零，亮部最多保留 32% 的原图色值。所有 ASCII 层先正常合成，再作为整体用 screen 模式与底光混合，保留屏幕和头发遮挡；转场同样包含底光。额外静态图片约 8 KiB，不增加逐帧取色、模糊或全景多帧缓存。云纹理向右以每秒 45 原图像素流动，是上一版 15 的 3 倍；颜色混合强度保持 0.78。

五只海鸥沿各自的闭合曲线飞行，穿插扇翼、滑翔和转弯。`flight-layer.js` 维护小型透明字符画布，`scene-layers.js` 让十一组漂浮物复用纹理、通过合成变换移动；Life 隐藏入口与小黄鸭使用同一时钟更新。其余约 1.8% 的字符独立轻微缩放，不使用全屏条纹。

`glyph-layout.js` 只在初始化或尺寸变化时计算排布：以固定随机种子释放格点，进行八轮按字形占地的局部避让；随后在最终位置重新取色。纸张、漂浮物共用这组点位，城市轮廓、海鸥和微小 LED 保留细节采样。排布不会在每帧重新计算。

`glyph-motion.js` 覆盖全部保留的背景字符，包括墙面、人物、天空、城市、窗框、太阳和水面底层。每个字符都有独立的 1.2–1.5 Hz 时钟和序列，不按矩形区域同步换字；使用 64 槽时间轮只处理到期字符，避免逐帧扫描全部位置；Canvas2D 的检查时刻各自错开，只补绘实际变化的笔画与相交邻居。邻居索引按实际坐标建立，补绘顺序保持与完整重画一致，避免跨越原格点后擦掉相邻笔画。普通帧最多替换 8192 个字符，初始化、缩放或长时间中断后直接同步当前状态，不积压旧帧。空位固定，换字与水波不会填满留白。字符库包含全部 94 种可见 ASCII（大小写字母、数字、标点），按实际笔画密度分组；每个颜色/密度组合选取四种候选字形，以不同起点与顺序循环，覆盖完整字符库并控制缓存。保留 RGB、坐标、字号与留白。

`glyph-batch.js` 在可识别的硬件 GPU 上批量绘制原有高 DPI 彩色字形纹理。静态字形以 6 Hz 合并绘制，各字的相位和速率仍独立；呼吸字号和衣角每帧恢复局部背景后单独绘制。GPU 背景缓存替代原来的 Canvas 底图，缩放时释放旧资源，上下文丢失后自动重建。软件 GPU、精度不足或纹理尺寸不支持时继续使用 Canvas2D 局部补绘。

`glyph-rhythm.js` 为海鸥、纸张、叶片、衣角、浮鸭、船和其他漂浮物，以及机器人眼睛/灯光提供独立的 1.2–1.5 Hz 字形节奏，每个字符的时间错开；很小的 LED 五官保留 `+`、`*` 两种发光点以保证清晰。漂浮物的字形纹理按 4 Hz 更新，表情面板按 8 Hz 检查字形，保持可见字符至少每秒变化一次；物体位置仍按显示刷新节奏移动。水面反光引用底层的字形状态；显示屏底纹以 2 Hz 刷新缓存，字形与波形符号加快轮换，代码和日志约每 0.8 秒滚动一行。

`sprite-atlas.js` 将原字形与替代字形紧凑排入固定图集，初始化后不再增长；背景沿用原有颜色量化，移动物件保留原始颜色精度和栅格相位。补绘从不可变图集直接绘入最终画布，保留相交邻居的完整笔画；移除频繁上传的中间画布，头发遮挡每帧最多重绘一次局部裁片。暂停和后台状态会同时停止全局换字、物体字形与位置动画。

`layered-scene.js` 在 Worker 中分别更新水面、云层、纸张、眼睛、三块屏幕和灯光。背景先烘焙一次，环境字符与全局字形变化时只更新小块像素；浏览器直接合成这些局部画布，每帧无需复制或传递整幅房间。显示屏用 CSS 四角透视，头发轮廓单独覆盖，转场通过 `scene-snapshot.js` 合成所有层。水面字符位置固定，涟漪包含更宽的亮波峰、较暗波谷和后续小波峰；波谷只在现有笔画上叠加至多 32% 的暗色，不填充字符之间的间隙，暗色字形复用同一个小图集颜色。`water-ripples.js` 保留四个主要起点，每 1.5 秒产生一轮（此前为 7.5 秒），并加入四处不同椭圆形状、大小和周期的细波，平均产生频率约为之前的 7.3 倍。多轮波纹各自扩散、平滑消退，宽度和速度按每轮固定种子轻微变化；约 4.5 KiB 的径向数组复用叠加后的波形，字符只查询相邻波场，不逐帧逐字遍历所有波纹。Worker 每秒采样 12 次亮度，三个有上限的局部缓冲提前准备相邻时刻；主线程按显示节奏做加法混合，使涟漪连续变化，避免每帧重绘和上传整片水面。海鸥、漂浮物与水波混合目标 60 Hz；波形与纸张由局部绘制更新，云纹理和灯光按 30 Hz 更新。实际帧率取决于设备，全部动作保持真实时间速度。

`render-budget.js` 保持优化前的高 DPI 分辨率（设备 DPR，上限 2），不按画面面积降采样；不降低采样预算、0.50–1.20 字号范围或取色精度。三块屏幕保留原来的 3 倍源纹理；云层、头发遮挡和灯光图层使用整数 CSS 边界，避免浏览器二次缩放细小字符。资源优化通过局部绘制与有上限的缓存实现：字形图集按实际字符/颜色去重，只打包笔画与透明边缘，动画中不增长；逐字补绘按设备像素对齐并裁剪纹理源坐标，避免逐字符的画布路径裁剪。烘焙后释放临时静态图集和源画布；灯光图集最多 2048 格，屏幕文字纹理最多 2 MiB / 384 项，缩放后释放旧显示缓冲。水面缓冲始终只有三个，传递后立即关闭 ImageBitmap。最多一个 Worker 请求在途，隐藏标签页和暂停时停止调度。缺少 Worker/OffscreenCanvas 或启动失败时回退到 Canvas2D；系统要求减少动态效果时默认暂停。

`scene-details.js` 定义机器人眨眼、黄鸭与泳圈的浮动、九张纸的固定点与风动、吊盆叶尖和云层区域。`scene-lights.js` 控制机械云变色呼吸灯（约每 0.8 秒呼吸一次，并每 0.8 秒平滑过渡到下一种颜色）、红眼目光以及两侧机器人的四种表情，`screen-content.js` 绘制三块屏幕。云层在窗框后漂移；太阳、城市与室内结构保持稳定。`glyph-atlas.js` 保留统一的背景取色和有上限的灯光缓存。[逐项动作设计与边界](docs/scene-motion.md)记录了受力方式、固定点和遮挡处理。

城市、人物与周围场景共用字形和颜色规则；远景建筑按轮廓固定使用 0.50 档，在原采样点之间补充半格错位点，保留建筑外的点位。边缘取色避免跨物体混色，天空使用稳定、逐字错落的混合字号；发丝按原图遮挡屏幕，保留发丝之间的背景空隙。`scene-geometry.js` 统一显示屏与左下机器人面板的四角透视。右侧显示区域扩到内侧 1–2 圈白色字符，人物头发仍遮挡显示器；屏幕内容亮度设为 85%，对应底光设为 40%，沿原平行四边形边缘柔化衔接。`scene-floats.js` 为船、罐子、纸张、平板、手机与玩具车配置独立的浮动周期和相位；加上黄鸭，共十一组漂浮物。

## 内容映射

`content/site.json` 是网站使用的本地内容快照，由 `content.js` 排版为技术文章、生活随记、文章详情和 CV。网页无需 Notion 令牌，也不会在访客浏览器中请求 Notion 或 Scholar API。原文链接保留在各页面。

当前快照收录 11 篇已发布文章（技术 2 篇、生活 9 篇）、111 张本地配图，以及 Scholar 的 18 条论文记录。

**来源访问：**发布后的新环境已验证可访问博客、Notion 公开站点与 Google Scholar。Notion 数据源使用公开站点，筛选 `Post`、`Published` 且未加锁的记录；忽略隐藏记录及菜单项。Scholar 资料仅使用公开姓名、机构、研究方向和论文，不推断未列出的履历。

内容快照格式：

- `notion.posts[]`：`id`（稳定的 Notion 页面 ID）、`category`（`tech` 或 `life`）、`title`、`date`、`summary`、`source`、`blocks`。
- `blocks[]`：`paragraph`、`heading`、`subheading`、`quote`、`code` 使用 `text`；`list` 使用 `items` 与可选 `ordered`；`link` 使用 `text` 和 `url`；`image` 使用 `url` 和 `alt`。
- 文章地址为 `/post/?id=<Notion 页面 ID>`，分类列表自动指向该地址，正文按本网站风格排版。文本不会作为 HTML 执行。`runs` 可保存段内链接；图片会保存到 `assets/notion/` 并通过相对路径读取，避免临时链接过期。
- `profile`：`name`、`affiliation`、`bio`、`interests[]`、`publications[]`、`source`、`syncedAt`。每篇论文含 `title`、`authors`、`venue`、`year`、`url`。仅在完成真实资料核对后填写 `syncedAt`。

这是可审阅的本地内容快照，不是自动同步服务。当前按来源页面 ID 保持映射；`LIFE` 与年度生活文章进入生活页，技术学习及 AI 相关笔记进入技术页。原文链接与原始分类保留在记录中。可使用公开来源或 Notion 官方导出的 Markdown/HTML ZIP 更新快照，不需要网站读者登录 Notion。

## 验证

环境已安装 Playwright 和 Chromium，启动上述静态服务后执行：

```sh
node tests/smoke.cjs
node tests/loading.cjs
node tests/responsiveness.cjs
node tests/layers.cjs
node tests/quality.cjs
TEST_GPU=1 node tests/quality.cjs
node tests/gpu.cjs
node tests/glyph-motion.cjs
# 单独运行，避免其他浏览器测试影响计时
node tests/performance.cjs
```

测试比较墙面、人物躯干、手臂、水面与三块屏幕，检查人物保持固定、屏幕独立更新、水面不出现黑缝，以及海鸥飞行范围、小黄鸭的移动入口与转场。还验证低帧率不会拖慢场景时间。

可通过 `TEST_ORIGIN` 和 `CHROMIUM_PATH` 指定测试服务地址和浏览器路径。测试覆盖实际图像点位跳转、手机触摸平移和旋转、隐藏入口、键盘、减少动态效果、转场、历史返回以及内容映射。测试不访问外部来源。响应测试会故意阻塞动画线程，验证海鸥仍持续移动和扇翼、Tech Blog 的悬停仍立即生效、渲染请求不积压、暂停丢弃迟到帧，并验证 Worker 启动失败、画布转移后的失败恢复。分层画面的实际浏览器截图与参考画面在静止和运动时对比，覆盖水面、头发、屏幕、云、浮鸭和纸张；长时间颜色变化验证灯光缓存上限。高分屏画质测试检查 DPR 2 下实际截图的字形清晰度与 RGB 偏差，以及显示屏的源纹理精度。性能脚本报告普通桌面、高分屏桌面和手机尺寸下的 Worker 帧率、水波插值帧率、帧间隔和绘图缓冲估算，支持 `PERF_OUTPUT` 保存 JSON，以及 `PERF_CASE=desktop|retina|mobile` 单独测量。

## 发布

仓库 **Settings → Pages** 使用 **master / (root)**。`.nojekyll` 允许直接发布静态文件，目录中的 `index.html` 支持子页直达与刷新。推送代码与 Pages 构建完成是独立步骤。
